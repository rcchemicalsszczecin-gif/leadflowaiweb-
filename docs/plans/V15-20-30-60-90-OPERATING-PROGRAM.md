## 3. Days 0–30 — establish first-party measurement

Priority order:

1. obtain/verify Google Search Console property access;
2. obtain/verify Bing Webmaster Tools access;
3. confirm sitemap/indexing state in each platform;
4. sample URL Inspection across homepage, service, local, knowledge and AI Search routes;
5. capture first valid 7/28-day query/page datasets when enough data exists;
6. attach measurements to the existing 63-URL V15.4 model;
7. identify real indexation blockers, weak query ownership, low-CTR opportunities and cannibalization only from evidence;
8. capture field CWV when the property/source exposes enough data;
9. decide whether IndexNow has a justified static-deploy use case;
10. keep new content/page creation frozen unless a distinct need is evidenced.

### Days 0–30 success condition

A trustworthy first-party baseline exists. Success is not defined as an arbitrary ranking target.

## 4. Days 31–60 — execute highest-confidence changes

Only after enough evidence:

- optimize titles/descriptions/H1/direct answers on pages with real query/CTR/relevance evidence;
- strengthen contextual links where measured ownership or user-path gaps justify it;
- consolidate proven cannibalization;
- update existing articles before creating new near-duplicate content;
- create a new article/page only for a distinct evidenced user problem;
- improve first-party screenshots/diagrams when they add proof or comprehension;
- implement IndexNow only if the real deployment/update model benefits from it;
- activate conversion analytics only if the separate V15.15 privacy/runtime authority has been granted.

Every material change enters the V15.19 change log with exact affected URLs and release SHA.

## 5. Days 61–90 — compare and decide the next cycle

When sample size/history supports interpretation:

- compare 28-day and longer query/page trends;
- identify winners, regressions and ambiguous changes;
- review branded vs non-branded discovery;
- review local/Szczecin query behavior;
- inspect field CWV trends and affected URL groups;
- review generative-AI Search reporting only where a real platform/property source exposes it;
- compare content clusters by useful discovery and commercial path, not article count;
- decide whether a dedicated local page is justified or would still create unnecessary overlap;
- admit original research only if a real auditable dataset has matured;
- define the next 90-day backlog from measured evidence.

## 6. Change discipline throughout the program

For every material search change:

- state hypothesis;
- identify evidence class;
- record affected canonical URLs;
- record exact revision;
- define expected signal;
- choose a sensible observation window;
- record actual result only from a real source;
- keep, revert or continue testing based on evidence.

Do not bundle unrelated visual/product/runtime changes into a search experiment.

## 7. Metrics that may be used after evidence exists

Examples:

- index coverage quality;
- impressions/clicks/CTR/average position by page/query;
- non-branded/local discovery;
- orphan/broken/cannibalization reduction;
- field LCP/INP/CLS;
- generative-AI visibility from a real property/source report;
- real qualified contacts/conversion only after authorized measurement.

No metric is guaranteed.

## 8. Permanent STOP rules

STOP when:

- a conclusion requires fabricated data;
- a page exists only to swap a city/keyword variant;
- canonical ownership is unclear;
- legal/business location facts are unverified;
- tracking/chat/lead runtime would be activated without authority;
- Quality/search/public-truth contracts fail;
- the requested change belongs to unrelated repository maintenance rather than V15 Search.
