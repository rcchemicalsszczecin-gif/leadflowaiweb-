## Preferowane terminy publiczne

- website / web → strona WWW / strona internetowa, zależnie od kontekstu;
- landing page → strona kampanijna, gdy nie jest używany termin branżowy w tytule usługi;
- development → programowanie / wdrożenie;
- design → projekt / projektowanie;
- responsive → responsywność;
- performance → wydajność;
- security → bezpieczeństwo;
- analytics → analityka;
- conversion → konwersja;
- lead → zapytanie, jeżeli nie chodzi o techniczny termin systemowy;
- deployment / launch → publikacja / wdrożenie / uruchomienie;
- maintenance → utrzymanie;
- backup → kopia zapasowa;
- fallback → tryb awaryjny;
- public truth → publiczna prawda / publicznie potwierdzone informacje;
- structured data → dane strukturalne;
- internal linking → linkowanie wewnętrzne;
- search architecture → architektura widoczności / architektura wyszukiwania;
- entity clarity → jednoznaczność encji;
- evidence → dowód / materiał dowodowy;
- claims → twierdzenia / deklaracje.

## Niedozwolone publiczne residue

Bez jawnego uzasadnienia technicznego nie publikujemy dawnych developer-demo etykiet takich jak:

`WHAT WE BUILD`, `FIRST-PARTY PROOF`, `EXPLORE`, `DRAG`, `INTELLIGENCE.`, `DIGITAL EXPERIENCE STUDIO`, `BUSINESS VALUE`, `CAPABILITY MAP`, `DIRECT ANSWER`, `SCOPE`, `PROCESS`, `RELATED`, `START`, `OPEN`, `LIVE DEMO`, `PROJECT COMMAND CENTER`.

## Reguła

Publiczny tekst ma być naturalnym językiem polskim. Termin angielski zostaje tylko wtedy, gdy jest nazwą własną, standardem, skrótem branżowym albo jego tłumaczenie obniża precyzję. Przy konflikcie między starym copy a tym dokumentem obowiązuje V13 Owner Authority + ten glossary.
