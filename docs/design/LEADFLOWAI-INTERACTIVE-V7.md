# LeadFlowAI — Interactive Experience V7

STATUS: OWNER-APPROVED IMPLEMENTATION STAGE
DATE: 2026-08-13

## Objective
Expand the public LeadFlowAI site from a strong visual shell into a demonstrable interactive product experience. V7 must show capabilities live in the browser while preserving the V5 realistic-hardware/water performance architecture and the V6 content-frame hierarchy.

## Locked visual foundation
- Realistic Hardware Water V5 remains authoritative for the fixed photographic motherboard background, WebGL water interaction and renderer performance bounds.
- Content Frames V6 remains authoritative for compact section indexes, readable technical frames, typography hierarchy and the prohibition on bulk backdrop blur.
- V7 extends the site with interactive proof; it does not replace V5/V6.

## Required V7 experiences
1. Live 3D showcase on the homepage using lightweight native browser 3D transforms, pointer response and no heavy third-party 3D dependency.
2. Interactive service cards for 3D/WebGL, interactive premium WWW and AI website capabilities.
3. Scroll-driven system assembly that activates successive WWW → Discover → Convert → Intelligence → Connect → Growth layers.
4. Live browser/window prototype with scenario switching and desktop/mobile viewport switching.
5. Before/after redesign comparison slider explicitly described as a concept demo, never as client work.
6. Capability constellation connecting WWW with 3D, SEO, AEO, GEO, AI, CRO and data/integrations.
7. Animated lightweight signal/data-bus separators between major experience blocks.
8. Project Command Center that configures project type and goal locally and opens direct e-mail contact; no lead backend is introduced.

## Live Lab
A public `/lab` route is required. It must collect the interactive demonstrations and explicitly state that the demos are running browser code, not fabricated client projects.

## Offer expansion
The public offer adds dedicated routes for:
- `/strony-3d-webgl`
- `/interaktywne-strony`
- `/motion-design`
- `/chatboty-ai`

Each route requires normal metadata, structured Service data through the shared service-page architecture, real scope language, process and FAQ. No ranking, conversion, performance or AI-output guarantees may be invented.

## Performance constraints
- Do not add a heavyweight 3D library merely for the homepage demo.
- The global V5 water renderer remains unchanged: eight ripple bound, bounded DPR, approximately 45 FPS cap, no scroll-driven shader.
- New motion must prefer transform/opacity and lightweight CSS/SVG.
- `prefers-reduced-motion` must stop continuous decorative motion while leaving functionality and information available.
- New interactive controls must work with keyboard focus where controls are semantic.

## Public truth
- Live demos are first-party demonstrators, not case studies.
- Before/after is marked as a neutral concept demo.
- AI chatbot remains an offered service, but the public LeadFlowAI chatbot widget stays OFF.
- Online lead delivery remains OFF; direct `kontakt@leadflowai.pl` contact stays authoritative.

## Exit criteria
PASS requires:
- all eight V7 interaction families present;
- `/lab` present and static-exportable;
- four experience service routes present and in sitemap;
- navigation/footer expose the new experience layer;
- V5 water/performance bounds preserved;
- V6 content-frame system preserved;
- typecheck, Biome lint, full repository verification, static export artifact checks and route smoke all PASS.
